# pkgsentinel 발표 대본 (출처 표기판)

---

**[슬라이드 1]**
안녕하세요, 7팀 캡스톤 '패키지센티널' 발표 시작하겠습니다. 발표에 앞서, 원래 저희 주제가 AI 슬롭스쿼팅 탐지 모듈이었는데, 범위가 좁고 부족해 보여 도중에 무산시키고 주제를 바꿔 처음부터 다시 5주간 진행했습니다. 보고서에 다른 점이 좀 있을 수 있습니다.

최근 AI가 코드를 생성·실행하면서 두 갈래 위협이 생겼습니다.
첫째는 슬롭스쿼팅입니다. LLM이 존재하지 않는 패키지명을 환각하고, 공격자가 그 이름을 선점합니다 *(슬롭스쿼팅 개념·환각률 선행연구: Spracklen et al., "We Have a Package for You: ... Package Hallucinations by Code Generating LLMs", USENIX Security 2024)*. 저희가 gpt-5.2·claude-opus-4-8로 1,000회 직접 측정했더니 *(자체 실험, 2026-05; OpenAI·Anthropic API)*, 추출 패키지의 3.1%가 레지스트리에 없는 환각 이름이었습니다 *(검증: PyPI·npm 레지스트리 API)*. 중요한 점은 환각이 예측 가능하다는 것입니다 — 동일 시퀀스 질문에서 5회 중 3회 이상 같은 환각을 보인 사례가 1/3이었습니다 *(자체 반복성 측정)*. 이는 공격자가 패키지명을 선점할 수 있다는 의미입니다.

둘째는 agentic 패키지입니다. MCP 서버가 출시 1.5년 만에 9,400개 이상 폭증했고 *(MCP 생태계 통계: DigitalApplied "MCP Ecosystem H1 2026", PulseMCP·Smithery·공식 MCP Registry 집계)*, npm 안에 'mcp' 키워드 패키지만 49,000개입니다 *(npm registry 검색 API, 2026-05)*. 그 안에 자격증명 탈취를 비롯한 악성 패턴이 등장했습니다 *(DataDog ai-skills 데이터셋)*.

**[슬라이드 2~3]**
해결책은 두 가지입니다. 탐지 엔진으로 지금 등록된 악성을 잡고, 제작자가 권한을 선언하게 해 위협을 구조적으로 줄이는 표준 제안입니다.

**[슬라이드 4 — 구조]**
전체 구조입니다 *(다이어그램: C4 model — Simon Brown, c4model.com)*. 개발자·CI/CD가 CLI나 API로 패키지를 검사하면, 분석 엔진이 아카이브를 설치 없이 메모리로 스트리밍해 분석합니다. 외부로는 PyPI/npm 레지스트리, OSV 인텔 *(Google OSV)*, MITRE ATT&CK *(attack.mitre.org)*, 그리고 코드 의미·버전 변경·선언 의존성을 각각 보는 3-에이전트 Claude API *(Anthropic Claude API)*와 프로토콜 단위로 연동하고, 결과는 SBOM·STIX·SIEM 표준 포맷으로 출력합니다.

**[슬라이드 5 — 7계층]**
탐지를 7계층으로 구성했습니다. 정적 분석, MITRE ATT&CK TTP 매칭 *(행위→ATT&CK 매핑 선행: Malware2ATT&CK, ScienceDirect 2024; 임베딩: Sentence-BERT all-MiniLM-L6-v2, Reimers & Gurevych 2019)*, 47개 악성 지표 *("Unveiling Malicious Logic..." arXiv:2512.12559, 2025)*, 테인트 분석 *(Taint-Based Slicing 기법)*, LLM 검증을 하나의 파이프라인으로 통합했습니다.

**[슬라이드 6 — Manifest]**
제작자가 파일·네트워크·셸 등을 매니페스트에 선언하면, 도구가 실제 탐지 행위와 대조해 미선언 권한을 경고합니다. 선언-탐지 대조 자체는 Android의 'permission gap' 연구에서 잘 검증된 패러다임입니다 *(Felt et al., "Android Permissions Demystified" / Stowaway, ACM CCS 2011)*. 모바일에서 검증된 이 패러다임을 신흥 agentic 패키지/스킬 영역으로 가져오고, 다중 어휘 정규화로 MITRE TTP 탐지 결과와 연결했습니다 *(선언형 권한 선례: Anthropic MCP 권한 모델; Gilbertson, npm 권한 제안 2018; mcp-sec-audit; 어휘는 Deno permissions·Google Capslock 차용)*.

**[슬라이드 7 — npm 비교]**
실제 데이터로 검증했습니다. DataDog 악성 패키지와 인기 정상 패키지를 조합해 npm 273개 데이터셋을 검사했습니다 *(악성: DataDog/malicious-software-packages-dataset, 시드 고정 무작위 추출; 정상: npm 인기 패키지)*. DB를 조회하지 않은 행위 기반만으로도 오탐이 없었습니다. 같은 데이터에서 Socket과 대등 이상입니다 *(비교: Socket.dev, OSV-Scanner)*.

**[슬라이드 8 — PyPI 비교]**
PyPI에서도 검증했습니다. 표준 Python SAST인 Bandit *(PyCQA)*, 다언어 SAST인 Semgrep *(Semgrep Inc, Docker 이미지)*과 비교했습니다. 범용 SAST의 한계가 보입니다. 또한 행위 기반만이면 오탐이 나오지만 LLM 교정으로 오탐이 2개까지 줄었습니다.

**[슬라이드 9 — zero-day]**
3개의 독립 명명 캠페인을 zero-day 환경에서 검증했습니다 — 2025-09 Shai-Hulud, 3주 전 Mini Shai-Hulud *(TeamPCP; Orca Security·The Hacker News 보도, 2026-05)*, 8일 전 TrapDoor *(The Hacker News 보도, 2026-05)*. 현재 구할 수 있는 패키지로 데이터셋을 구성했습니다 *(DataDog 데이터셋)*. npm의 Bandit 격인 njsscan과 비교했고 *(njsscan, MobSF/OpenSecurity)*, OSV 0%는 DB 영향이 없는 zero-day를 가정한 지표입니다 *(Google OSV)*. 페이로드 없는 decoy 6개를 제외하면 90%입니다.

**[슬라이드 10 — 남은 과제 ai-skills]**
남은 과제입니다. DataDog 데이터셋 중 최근 ai-skills 패키지셋은 결이 다른 zero-day입니다 *(DataDog ai-skills 카테고리, 2026-05 신설)*. 공격이 코드가 아닌 markdown 지시문 자체에 있습니다. 지시문 분석 모듈 markdown-pinpoint를 만들어 넣었더니 탐지율이 소폭 상승했습니다 *(프롬프트 인젝션 패턴은 Sentry skill-scanner(getsentry/skills)에서 적응; 스킬 공격 선행: Snyk ToxicSkills·SkillRisk·Invariant Labs tool-poisoning·OWASP MCP Top 10)*. 이처럼 권한을 선언시켜 매니페스트로 만들면 미선언 행위 탐지에 긍정적입니다.

발표는 여기까지입니다. 감사합니다.
