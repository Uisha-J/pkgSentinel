pkgsentinel: AI 시대 소프트웨어 공급망 악성 패키지 탐지 엔진 및 Agentic Capability Manifest

7팀 캡스톤 최종 보고서 · 2026-05-31

1. 프로젝트 개요

1.1 배경

대규모 언어 모델(LLM)이 코드 생성·실행에 광범위하게 사용되면서 소프트웨어 공급망에 두 가지 새로운 위협 표면이 형성되었다.

(1) 슬롭스쿼팅(slopsquatting). LLM은 실제로 존재하지 않는 패키지명을 추천하는 환각(hallucination)을 일으킨다. 공격자가 이 환각 패키지명을 레지스트리(PyPI·npm)에 미리 등록(선점)하면, AI 추천을 신뢰한 개발자가 악성 패키지를 설치하게 된다. 레지스트리는 업로드 시 코드 리뷰를 수행하지 않으므로, 공격자 등록 시점부터 레지스트리 측 삭제 시점까지의 시간 창(time window)이 공격 기회가 된다.

(2) Agentic 패키지·스킬. Model Context Protocol(MCP) 서버와 AI 에이전트 스킬(SKILL.md 기반)이 급증하면서, 파일·네트워크·셸 권한을 보유한 패키지가 늘어났다. 이 영역에서는 악성 로직이 실행 코드가 아니라 AI 에이전트에게 주어지는 자연어 지시문에 위치하는 새로운 공격 형태가 등장했다.

1.2 목적

본 프로젝트는 레지스트리에 등록되어 있으나 악의적인 패키지를, 설치·실행 없이 정적으로 탐지하는 엔진을 구현하고, 실제 악성 패키지 데이터셋 및 표준 비교 도구를 사용해 성능을 측정하는 것을 목적으로 한다. 또한 패키지·스킬 제작자가 필요 권한을 사전 선언하고 도구가 실제 탐지 행위와 대조하는 Agentic Capability Manifest 표준을 제안한다.

1.3 위협 모델

LLM 환각/agentic 패키지 → 공격자 레지스트리 등록 → AI 추천 신뢰 설치 → 악성코드 실행
                                          │
                              pkgsentinel가 메우는 구간
                          (등록 시점 ~ 삭제 시점 time window)

탐지 대상: 자격증명 탈취, 원격 코드 실행(RCE), 설치 훅(install-hook) 기반 송출, 난독화 페이로드, 버전 간 악성 코드 주입, 스킬 지시문 인젝션.

2. 시스템 구조

2.1 분석 원칙

  • 패키지 아카이브를 디스크에 설치하지 않고 메모리로 스트리밍하여 핵심 파일만 추출·분석한다.
  • 판정은 추출된 증거(Evidence)와 단계 실행 결과만으로 결정하며, 패키지의 등록일·인기도·다운로드 수는 판정에 사용하지 않는다.
  • 필수 단계(행위 시퀀스, TTP 매칭, LLM 검증) 중 하나라도 실패하면 부분 판정을 내리지 않고 ERROR로 종료한다.

2.2 7계층 / 21단계 파이프라인

탐지 로직은 7계층(L0–L6)으로 구성되며, 실제 실행은 21개 단계(stage_00–stage_20)로 순차 수행된다. 계층 구조의 설계 의도는, 비용이 낮고 결정적인 검사(레지스트리 조회·DB 매칭)를 앞단에 두어 조기에 판정을 단축하고, 비용이 높은 분석(임베딩 매칭·LLM 검증)을 뒤로 배치하는 것이다. 각 단계는 산출한 증거(Evidence)와 실행 결과(StageResult)를 다음 단계로 누적 전달하며, 최종 판정(stage_20 직후)에서 누적된 증거 전체를 근거로 판정을 결정한다.

단계는 역할에 따라 세 종류로 구분된다. (a) 게이트 단계는 조건 충족 시 후속 분석을 생략하고 즉시 판정을 확정한다(stage_00 미등록, stage_01 known-malicious, stage_07 agentic 악성). (b) 필수 단계(stage_08·11·16)는 판정의 근거가 되며, 하나라도 실패하면 부분 판정 없이 ERROR로 종료한다. (c) 참고 단계(stage_03·04·20)는 메타데이터를 수집해 리포트에 포함하지만 판정값에는 직접 반영하지 않는다 — 판정이 패키지의 평판·인기도·출처 신뢰도가 아니라 코드 행위에만 근거하도록 분리한 것이다.

위 단계 중 게이트 단계는 조기 종료를 통해 명백한 케이스(미등록·기지 악성·agentic 악성)에서 불필요한 연산을 생략한다. L3 패턴 매칭 계층은 단일 기법에 의존하지 않고 문자열 분석·버전 diff·TTP 매칭·지표 매처·시퀀스 마이닝·테인트 분석을 병렬적으로 적용하여 서로 다른 각도에서 증거를 수집한다. L4 LLM 검증은 L2–L3가 수집한 증거를 문맥적으로 재평가하여, 정상 패키지에서 발생한 약한 신호를 강등하고 실제 악성 신호를 확정하는 정밀도 조정 역할을 한다.

성능 측정 시에는 L0의 위협 인텔 조회(stage_01)를 비활성화하여, DB 매칭이 아닌 순수 행위 기반(L2–L4) 분석 성능을 측정하였다.

2.2.1 MITRE ATT&CK TTP 매칭 (stage_11)

TTP(Tactics, Techniques, and Procedures)는 공격자의 행위 패턴을 분류한 체계로, MITRE ATT&CK이 업계 표준 지식베이스를 제공한다. 본 단계는 패키지의 코드 행위를 ATT&CK 기법과 의미 수준에서 대조하여, 정확한 문자열·시그니처가 일치하지 않더라도 의미가 유사한 변종 행위를 탐지하는 것을 목표로 한다. 처리 과정은 stage_08이 추출한 각 파일의 행위 시퀀스(FileSequence) 단위로 다음과 같이 수행된다.

  1. 시퀀스 → 자연어 변환. 행위 시퀀스를 임베딩 모델이 처리할 수 있는 문장으로 변환한다. 4개 공격 차원(민감정보 읽기·인코딩/난독화·동적 코드 실행·원격 전송)의 요약과 API 호출 체인(call_a -> call_b -> ...)을 결합한 영문 서술을 생성한다.

  2. 임베딩. 변환된 문장을 Sentence-BERT 계열 문장 임베딩 모델(all-MiniLM-L6-v2)로 벡터화한다.

  3. Top-K 검색. MITRE ATT&CK 기법을 동일 모델로 사전 임베딩해 둔 로컬 인덱스(mitre_attack_embedded.json)에서 코사인 유사도 기준 상위 K개(기본 K=3) 후보를 검색한다.

  4. 임계값 적용. 유사도에 따라 신호 강도를 구분한다. - 0.50 미만: 잡음으로 간주하여 무시. - 0.70 이상: 후보 매칭으로 채택(STRONG_THRESHOLD). - 0.85 이상: 강한 매칭으로 간주하여 HIGH_RISK/MALICIOUS 분기 조건에 사용(VERY_STRONG_THRESHOLD).

  5. 규칙 기반 보강. 임베딩이 놓칠 수 있는 결정적 패턴을 규칙 매칭(apply_rules)으로 보강한다. 규칙 적중은 결정적 매칭이므로 유사도 1.0으로 기록되어 임베딩 매칭과 함께 후속 단계로 전달된다.

이 단계의 매칭 결과(파일 경로, 시퀀스, 매칭된 TTP, 유사도)는 stage_16 LLM 검증의 입력으로 사용되며, 강한 매칭(유사도 ≥ 0.85, severity ≠ LOW)은 LLM 판정과 무관하게 위험 분기로 진입한다. 반대로 약한 매칭(유사도 0.70–0.85, severity LOW)에 대해 LLM이 BENIGN으로 판정하면 해당 신호는 승격되지 않는다(2.3 참조).

2.3 판정 규칙

판정 조건
MALICIOUS high-severity TTP ≥ 1 AND LLM=malicious AND 최강 악성 증거 confidence ≥ 0.85
HIGH_RISK (TTP match ≥ 1 OR version_diff critical) AND LLM ∈ {suspicious, malicious}
SUSPICIOUS weak TTP(LLM≠BENIGN) OR version_diff any OR LLM-only suspicious(confidence ≥ 0.5, quorum 2)
CLEAN 전 단계 통과 AND 증거 없음, 또는 weak TTP + LLM=BENIGN
ERROR 필수 단계(08/11/16) 중 1개 이상 실패
CANNOT_ANALYZE stage_00 미등록 확정

LLM의 BENIGN 판정은 약한 TTP 신호(유사도 0.70–0.85, severity LOW)를 덮어쓴다. 강한 매칭(유사도 ≥ 0.85, severity ≠ LOW)은 LLM 판정과 무관하게 위험 분기로 진입한다.

2.4 Agentic Capability Manifest

제작자가 필요 권한(파일·네트워크·셸·환경변수 등)을 매니페스트에 선언하면, 엔진이 stage_07–16에서 실제 탐지한 행위(capability)와 대조하여 미선언 권한을 식별한다. 도구별로 상이한 권한 표현(self 27종, MITRE 28종)은 15개 표준 capability 어휘(filesystem-read/write, shell, network, env-secrets, code-exec, credential-paths, db-access, mcp-client/server, llm-call, tool-loop, memory-persistent, dynamic-tool-load, agent-to-agent)로 정규화하여 선언과 탐지를 동일 어휘로 비교한다.

2.5 표준 출력 포맷

CycloneDX 1.5 VEX, STIX 2.1 / TAXII 2.1, HMAC 서명 웹훅, Falco rules · Tetragon TracingPolicy, SafeDep pmg policy.
